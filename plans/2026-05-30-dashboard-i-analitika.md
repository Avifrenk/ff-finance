# План: Фаза 3 — Дашборд и аналитика (бюджеты + сравнение месяцев + календарь)

Цель ветки `feat/dashboard` — закрыть Фазу 3 из ROADMAP. После этой ветки на главном экране появляется внятная аналитика: что и куда потрачено в этом месяце по категориям (pie + bar), как это сравнивается с прошлым, какие категории уже переедают бюджет, и какие платежи нас ждут в этом месяце по календарю.

Это первая ветка, где UX явно идёт под Аватар 2 (жена) — дашборд это первое, что она увидит, поэтому фильтр «поймёт ли с первого раза без объяснений?» применяем к каждому виджету.

## Принципы

- **Слоями.** Бюджеты — отдельная таблица + RLS + UI; разбивка по категориям и сравнение месяцев — чистая агрегация на клиенте поверх уже грузимых operations; календарь — поверх `operation_schedules`. Ничего не блокирует ничего, можно мержить и подфазами.
- **Считаем на клиенте.** Для семьи это сотни операций в месяц, на 200-300 строк pie/bar/totals считаются мгновенно. SQL-view-ы и материализованные суммы — преждевременная оптимизация (как и в Фазе 2.7).
- **Всё, что миксует валюты — через `convertMoney`** в `households.base_currency`. Бюджет хранится в `base_currency` (одна цифра «жена сказала на продукты 3000 ₪»), а расходы по категории сравниваются с ним после конверсии. При смене base_currency бюджеты не пересчитываются — просто перевыводятся в новой валюте.
- **Двухуровневая приватность сохраняется** автоматически: pie/bar/сравнение/прогресс бюджета считаются по `operations`, которые уже отфильтрованы RLS + `viewMode`. Партнёр видит свою «версию правды» — это правильно.
- **RLS с первого дня + GRANT-ы явные.** Учим урок Фазы 2.10 (`service_role` не имеет default privileges в этом проекте — если что-то трогает Edge Function, GRANT обязателен). В Фазе 3 ничего не трогает service_role, но GRANT на `authenticated` всё равно явный.
- **Графики — чистый SVG/CSS.** Pie на 5-10 категориях рисуется инлайн-`<path d="A …">` строк на 30 — это меньше, чем интеграция recharts. Bar — это `<div>` с `width: ${pct}%`. Никаких UI-библиотек поверх Tailwind. Если на каком-то виджете SVG-математика растягивается — тогда подключаем recharts точечно (открытый вопрос).
- **UX-фильтр на каждый виджет:** «поймёт ли жена с первого раза, без объяснений?». Если для понимания нужен tooltip «как это считается» — виджет переусложнён, упрощаем или режем.

## Открытые вопросы

- **Donut или horizontal bar по умолчанию?** Кажется, donut приятнее визуально, но на mobile места меньше. План: на mobile (`< sm`) bar'ы, на desktop donut + список. Решение по факту в Фазе 3.2.
- **Recharts всё-таки или нет?** Принцип говорит «сначала попробуй SVG руками». Если donut с подсветкой сегмента и анимацией займёт > 100 строк — подключаю recharts (lightweight, ~50 kB gzipped) точечно только для donut, всё остальное оставляю руками. Решение по факту в Фазе 3.2.
- **Календарь — виджет или отдельная страница?** Склонен к виджету в самом низу Dashboard. Если на mobile занимает экран целиком — выношу на `/calendar` отдельной вкладкой. Решение по факту в Фазе 3.7.
- **Бюджет в валюте семьи или счёта?** Решено: в `base_currency` семьи. Без `currency` в таблице. См. Фазу 3.4.
- **«Перенести» бюджет?** Если в апреле потратили меньше — переносить ли остаток в май? Нет, в этой ветке — нет. Это «бюджет-конверт» (envelope budgeting), отдельная фича. Сейчас бюджеты независимы по месяцам.
- **Уведомления «потрачено 80%»?** Только визуальная подсветка в виджете. Web Push — Фаза 8 (полировка/деплой). Поэтому ROADMAP-пункт «Месячные бюджеты по категориям + предупреждения» в этой ветке закрывается именно визуальной частью.

## Инварианты

- Всё, что миксует валюты (бюджеты, totals, pie, дельта месяцев) — через `convertMoney` в `base_currency`.
- Бюджеты хранятся в `base_currency` семьи, без поля `currency` в таблице. При смене базовой валюты семьи бюджеты остаются цифрой как есть (просто перевыводятся в новой валюте).
- Двухуровневая приватность сохраняется автоматически: агрегаты считаются по `operations`, отфильтрованным RLS + viewMode. Партнёр видит свои pie/bar/budget-прогресс, отличающиеся от пользовательских.
- Никаких UI-библиотек поверх Tailwind. Графики — inline SVG; recharts — только если donut с подсветкой не вылезает в SVG в разумное число строк.
- RLS вместе с `CREATE TABLE budgets`. GRANT для `authenticated` явный. Service_role не трогаем — этот слой полностью клиентский.
- `transfer_id != null` исключены из всех агрегатов (как уже сделано в Dashboard и Operations).
- UX-фильтр: каждый виджет, который оставляем — жена понимает с первого раза, без объяснений.

## Не входит в эту ветку (намеренно)

- **Цели и подушка безопасности** — Фаза 4.
- **Тренды / прогнозы / аномалии** — заявлено в фичах, но не блок Фазы 3 в ROADMAP. Если pie + сравнение месяцев + бюджеты + календарь зашли — тренд (sparkline за 6 месяцев) можно добавить отдельной маленькой веткой `feat/dashboard-trend`.
- **Push-уведомления** «бюджет 80% / превышен» — Фаза 8 (Web Push). Сейчас только UI-подсветка.
- **Envelope budgeting** (перенос остатка с месяца на месяц) — отдельная фича, если когда-нибудь захочется.
- **Drag-n-drop в календаре**, редактирование расписания прямо из ячейки — переусложнение, не входит.
- **Аналитика крипты / P&L** — Фаза 5.
- **AI-ассистент «сколько на ресторанах в апреле?»** — Фаза 6.

## Деплой миграций к prod-БД

Как в фазе 2.10 — direct connection (pooler после ротации пароля 2026-05-28 кешируется, поэтому идём через `db.<ref>.supabase.co:5432`):

```
npx supabase db push --db-url \
  'postgresql://postgres:<password>@db.cngrrvfqwaqfydmfhiex.supabase.co:5432/postgres' \
  --yes
```

Пароль — в `.env.local` у пользователя. PAT для этой ветки не нужен — Edge Functions в Фазе 3 не трогаем (`fetch-ecb-rates` уже живой, `tick_schedules()` уже на pg_cron). Если по ходу выяснится, что нужен — попрошу PAT отдельно.

## Итог

Реализовано в ветке `feat/dashboard`:

- **Чистые хелперы (`src/lib/aggregate.ts`, `src/lib/period.ts`, `src/lib/scheduleExpand.ts`):** `monthRange/previousMonthRange/last30DaysRange/quarterToDateRange`, `monthTotals`, `aggregateByCategory`, `collapseTail` (свёртка хвоста в «Прочее» с защитой от свёртки одной строки), `expandCadenceInMonth` для daily/weekly:dow/monthly:N, `monthGrid` для 6×7 календарной сетки. Без I/O, конвертация валют — через `convertMoney`.
- **Общий `<PeriodPicker>`** (4 таба: «Этот месяц / Прошлый / 30 дней / Квартал»). Управляет агрегатами текущего/прошлого периода и pie/bar на Dashboard.
- **Pie/bar по категориям расходов** (`CategoryBreakdown`): inline-SVG donut (без recharts) с подсветкой сегмент↔строка списка, плюс компактный список «Доходы». Свёртка >8 категорий → «Прочее (N)». Пастельная палитра по индексу если у категории нет своего `color`. Mobile-friendly (donut скрывается при ≤1 категории, на узком экране список идёт под чартом).
- **Сравнение «этот период vs прошлый»** (`MonthCompareCards`): пара карточек + 3 дельты (Δ Доход, Δ Расход, Δ Итог) в ₪/процентах, цвет дельты с учётом «положительная для дохода — это хорошо, для расхода — плохо». Edge case: если за прошлый период нет ни одной операции — пишем «нет данных», не считаем «−100%».
- **Бюджеты:**
  - Миграция `20260530100000_budgets.sql`: таблица `budgets(household_id, category_id, month, amount, created_by, created_at, updated_at)` с unique-индексом `(household_id, category_id, month)` и индексом `(household_id, month)`. RLS с первого дня; SELECT/INSERT/UPDATE/DELETE для членов household; INSERT с CHECK `created_by = auth.uid()`. GRANT-ы явные на `authenticated`.
  - Хук `useBudgets(month)` + `useBudgetsByCategory(month)` со стандартным паттерном (`CustomEvent('ff:budgets-changed')`, debounce между страницами). `upsert/remove/copyFromPreviousMonth`. **Defensive:** при ошибке `42P01 (relation does not exist)` тихо возвращает пустой список — UI не падает, если миграция ещё не применена в БД.
