# plans/

Папка для технических планов реализации функций проекта.

## Правила

1. **Один план = одна функция.** Не смешиваем несколько фич в одном файле.
2. **Имя файла:** `YYYY-MM-DD-название-функции.md` (дата создания плана, kebab-case).
3. **Структура плана:** делится на **фазы**. У каждой фазы статус-чекбокс:
   - `[ ]` — не сделано
   - `[x]` — сделано
4. **Итоговый блок в конце плана** — короткое резюме: реализован ли план целиком, что осталось, что было отложено и почему.
5. **Актуализация — обязательна.** Любой агент (или человек), работающий с планом, обновляет его в этой же сессии: отмечает закрытые фазы `[x]`, дописывает что именно сделал, что выяснил, что изменилось в подходе. План — живой документ, а не разовый чек-лист.
