# Frenkel Family Finance — навигация по проекту

Этот документ — карта проекта. Читай его в начале каждой сессии, чтобы понимать, где что лежит и как с этим работать.

## Что это за проект

**Frenkel Family Finance** — PWA-приложение для семьи (пары) для учёта, анализа и прогноза финансов. У каждого супруга — личная зона, поверх — общий «семейный» слой: траты, доходы, бюджеты, цели, крипта, AI-помощь.

Контекст: пользователи в Израиле, основная валюта — ILS, учитывается местная специфика (арнона, ваад, купат холим). Это личный пет-проект пары — без коммерции, без других пользователей.

Подробности — в [.business/INDEX.md](.business/INDEX.md).

## Ключевые принципы проекта

1. **🔒 Приватность и контроль над данными.** Семейные финансы — глубоко личное. Свой бэкенд (Supabase под контролем владельца), никаких сторонних финтрекеров.
2. **🌸 Простота для супруги.** UX оптимизируем под Аватар 2 (жена). Если что-то требует объяснения — это плохой UX. Фильтр для каждого экрана: «поймёт ли она с первого раза без объяснений?»
3. **🎯 Глубина и точность учёта.** Полная финансовая картина без упрощений: мультивалюта, крипта, прогнозы, P&L. Трейд-офф: глубина данных есть всегда, но по умолчанию интерфейс упрощённый — продвинутое прячется за «Дополнительно».

Подробности — в [.business/company/values.md](.business/company/values.md).

## Стек

- **Frontend:** Vite + React 19 + TypeScript + Tailwind v4, React Router 7
- **PWA:** vite-plugin-pwa (офлайн, иконка на home screen)
- **Backend:** Supabase (Postgres + Auth + Realtime + Storage), двухуровневый RLS
- **AI:** Claude API (Vision для чеков, Haiku для ассистента, Whisper для голоса)
- **Цены крипты:** CoinGecko REST + Supabase Edge Function (cron раз в час)
- **Курсы валют:** ECB API (исторические курсы на дату операции)

## Как работать с проектом

- Перед любой задачей — прочитай этот файл, затем нужные документы из `.business/` и `plans/`.
- Если меняется бизнес-логика — обнови `.business/INDEX.md` и нужные файлы.
- Если меняется технический план — обнови соответствующий план в `plans/`.
- Если появляется новая важная папка или документ — обнови этот `CLAUDE.md`.

## Применение миграций к prod-БД

Не пытайся читать `.env.local` через shell — глобальный hook у пользователя
блокирует. DB-пароль там и не лежит. Вместо этого:

```
npm run db:push
```

Скрипт `scripts/db-push.mjs` сам подхватит connection-URL из `FF_DB_URL`
(env) либо из `~/.config/ff-finance/connection` (одна строка
`postgresql://postgres:<password>@db.<ref>.supabase.co:5432/postgres`).
Если файла нет — скрипт выведет инструкцию первичной настройки.

После одноразовой настройки пользователю не нужно участвовать ни в одной
миграции: применяй `npm run db:push` каждый раз сам.

## ВАЖНО: план для каждой новой функции

Любая функция, которую мы создаём в любом чате, всегда оформляется планом в папке `plans/`.

Правила:

1. Один план = одна функция. Если план уже есть — работаем с ним.
2. Имя файла: `YYYY-MM-DD-название-функции.md`.
3. План делится на фазы. У каждой фазы статус `[ ]` или `[x]`.
4. В конце плана — итоговый блок: реализован целиком или нет, что осталось.
5. Любой агент обязан актуализировать план после каждой сессии.

## ВАЖНО: завершение каждого чата

В конце каждой сессии записывай рефлексию в файл `.business/история/YYYY-MM-DD-краткое-название.md` (создавай папку при необходимости).

Формат:

1. Какая задача была поставлена.
2. Как я её решал.
3. Решил ли — да / нет / частично.
4. Эффективно ли решение, что можно было лучше.
5. Как было и как стало.
